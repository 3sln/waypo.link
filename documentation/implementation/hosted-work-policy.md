# Explicit work policies for hosted compositions

> Source-development reference: open-source Waypo commit `188eb16` selected by this isolated hosted candidate. Public operation remains disabled; work units and example policies are not financial approval.

This is provider implementation/deployment policy, not an OIDC or Waypo extension requirement. Private self-hosted installations retain opt-in work admission. Hosted compositions call `validateHostedWorkConfiguration(config)` from `@3sln/waypo/configuration` before runtime resource allocation.

Every hosted identity configuration must supply a complete finite `tokenWork` policy, even when registration is closed. Closed registration still exposes sign-in and token endpoints for existing accounts. When `services.sync`, `notifications` or `signaling` is enabled, complete `services.workBudget` and `services.workPeriodBudget` policies are also required. The latter declares included essential reserves and fixed UTC daily/monthly absolute work ceilings; explicit operator activation is documented in [the period-wallet contract](work-period-budget.md). Attachments and subscriptions require enabled sync. Service flags are booleans, never strings. Disabled optional modules may omit the service work policy; any supplied policy is validated even when its module is disabled.

The exported pure `validateTokenWorkConfiguration` and `validateServiceWorkConfiguration` functions are the same validators used by their runtime factories. They reject unknown policy/bucket/weight fields, non-finite or out-of-range values, missing dimensions, and a work cost that cannot fit its bucket. Validation returns normalized copies without allocating engines, stores or network transports. Service active-app/idle defaults remain finite when omitted; null or explicitly malformed values are rejected.

Token policy fields: `revision`, `reservationUnits`, `costs` (`lookup`, `refresh`), `maxFamilies`, `inactiveFamilyMs`, and `lookup`, `account`, `family`, `fleet` buckets. Each bucket has `capacity` and `refillPerMinute`.

Service policy fields: `revision`, `reservationUnits`, all seven documented service `costs`, and `account`, `app`, `fleet`, `ingress` buckets. `maxActiveApps` and `inactiveAppMs` may be supplied explicitly. The runtime service/token modules remain responsible for prepaid credit ownership, revocation checks, policy migration behavior and Retry-After.

Completeness is a startup safety contract, not cost approval. Finite rate buckets and period ceilings count operator-defined work units; they do not stop raw inbound Worker charges, cover every owner/admin/support endpoint, or prove adequate Native retained-row/storage capacity. The mounted period-wallet seam covers service lookup, app service reservations, shard work blocks and current owner-storage maintenance; token, push, support, email and additional administrative adapters remain separate. Engineering examples in a closed hosted configuration must not be presented as approved public launch limits. Initial free storage and signaling remain independent of billing.
