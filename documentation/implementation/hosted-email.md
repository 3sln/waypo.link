# Hosted Email Sending transport contract

`email-transport.mjs` is an internal Waypo.link leaf for the current structured Cloudflare Email Sending Workers binding. Hosted Worker composition installs the private bridge for a callable native `env.EMAIL.send` only with an actual shared budget DO binding, explicit budget config and key; missing required admission infrastructure fails closed. There is no package export or public mail endpoint. The default Wrangler configuration has no send binding, and DNS onboarding/live-send readiness remain unverified. Production remains disabled. Before enabling native sending in production, hosted orchestration must enforce durable fleet and recipient rate limits plus explicit spend/message budgets using bounded work-budget or prepaid ports. Binding availability and existing native flow caps alone do not establish economic readiness. Budget values require deployment configuration; this leaf invents no commercial limits or prices. Audit public-signup human/mail-flow admission as part of that release gate.

```js
const deliverEmail = createHostedEmailTransport({
  emailBinding: env.EMAIL,
  origin: 'https://waypo.link',
  trustedLoginOrigins: ['https://waypo.link'],
});
```

This is an eventual trusted-composition example, not an instruction to run a live send. A separately configured admin origin may be included explicitly in `trustedLoginOrigins`; there is no automatic subdomain/wildcard trust and request JSON cannot add origins. The sender domains are the user-selected login/account/notify separation; the localparts and display names below are engineering defaults.

| Internal purpose | Fixed sender | Current caller status |
| --- | --- | --- |
| identity-login | login@login.waypo.link | Existing core message shape supported |
| identity-session-recovery | login@login.waypo.link | Purpose-specific budgeted transport available; Native feature mount remains separately qualified |
| account-lifecycle | account@account.waypo.link | Existing core maintenance shape supported |
| account-security | account@account.waypo.link | Reserved future caller |
| app-notification | notifications@notify.waypo.link | Reserved future caller |
| app-digest | notifications@notify.waypo.link | Reserved future caller |

The internal caller must derive purpose and app sender identity from trusted server state, never arbitrary application metadata. App purposes require a server-derived exact HTTPS `senderOrigin` and receive fixed app-attribution text outside the app-supplied title/body. This leaf does not itself prove URL ownership or enable app email routes.

`identity-login` accepts `{to,purpose,url,code,createdAt?}`. The URL must match an exact configured trusted origin and `/email`, have no query or credentials, and use only the canonical `#flow=...&token=...` fragment. Flow/token values are bounded URL-safe strings. The actual portable provider currently generates an eight-digit zero-padded decimal code and a ten-minute request lifetime; the template follows that implementation, not a guessed six-digit OTP convention. Sender/subject/text are generated by the leaf.

`identity-session-recovery` is authentication mail, not an account-lifecycle notice. It shares the existing login pool and recipient throttle with identity login; an anonymous discovery request cannot consume the reserved lifecycle-notice lane. The main OIDC issuer remains `https://waypo.link/api/auth` and its recovery page remains at `https://waypo.link/recover-browser`; `login.waypo.link` is the sending domain, not a new issuer or callback origin.

Its closed payload is `{to,purpose,createdAt,url,recoveryKind,browser?}` plus the existing optional job/idempotency fields. The exact main-origin URL has no query and only canonical `#operation=<43 URL-safe characters>&token=<32..256 URL-safe characters>`. There is no verification-code field. `discovery` messages offer review of signed-in browsers without signing in. `retire-browser` requires only a coarse80-character browser label and creation/expiry timestamps, and names the one provider browser affected. Both make clear that application access stays connected and ordinary sign-in is separate. Unknown/native-ID/cookie/token/sender fields, wrong origins/paths, malformed fragments and injected labels reject **before** budget admission or sending.

Recovery readiness is purpose-specific: only the exact immutable issuer-bound transport object created with the genuine shared budget capability is registered for `identity-session-recovery`. Old issuer-only brands, JSON flags, clones and generic hooks do not opt in. The portable registration API accepts an immutable copied closed purpose list; its third-argument readiness predicate checks the required purpose. This changes neither the existing two-argument compatibility check nor the requirement for an actual qualified human/Native recovery caller. Leaf support is not proof that a hosted recovery feature is mounted or that a vendor delivered mail.

Account purposes accept a bounded subject/title and text/body, optional main-origin URL and existing job/idempotency/creation metadata. Plain LF/TAB body formatting is accepted; CR and other control characters reject. App purposes add required senderOrigin. Every recipient is one plain mailbox string, at most 254 UTF-8 bytes; arrays, address lists and display-name syntax reject. Unknown purposes/fields, sender/cc/bcc/headers/HTML/attachments, malformed links, control injection and oversized data reject before sending. This is an explicit bounded plain-mailbox profile, not a claim to implement every legal RFC mailbox syntax.

The native call is exactly one `emailBinding.send({to,from:{email,name},subject,text})`. No raw MIME, custom headers, HTML, binary attachments, REST fetch fallback or automatic retry is used. Existing job/idempotency metadata is not a provider-level deduplication guarantee. An ambiguous failure can still represent an already accepted message; eventual orchestration must not promise exactly-once email delivery.

A successful native result must include a bounded messageId and maps to `{status:'accepted',messageId}`. That means API acceptance only, not inbox delivery, recipient engagement or a human check-in. Missing binding maps to unconfigured. Sender/domain/allowed-destination setup errors are unconfigured; account suspension, quotas, rate limits and generic delivery errors are outages. Only the explicit recipient-suppression error is a permanent recipient-specific rejection. No provider error message, recipient address, login URL/token or verification code is logged or copied into failure results.

The bridge is a private in-process `EMAIL_TRANSPORT.fetch` capability at exact `POST https://mail-transport.invalid/send`, with application/json input bounded to 128 KiB by streaming reads. It cancels oversized bodies and does not trust Content-Length. Hosted composition reuses the portable deployment validator, including the Worker authSecret overlay, to derive exact main/admin login origins; that overlay is not copied into WAYPO_CONFIG. An explicit existing EMAIL_TRANSPORT is preserved when no EMAIL binding exists. Supplying both bindings, or a present EMAIL without callable send, rejects instead of silently overriding/downgrading. Do not fabricate `emailDeliveryUrl`/token configuration to satisfy readiness checks. Presence of a binding is configured capability, not externally verified sender-domain readiness; the native service can still reject it. Bridge responses use X-Waypo-Email-Result:v1 plus bounded structured status JSON. The portable Worker interprets only that explicit profile, bounds its body to 4 KiB, drops provider diagnostic fields, rejects unknown/malformed marked profiles as outages, throws generic nonacceptance for identity-login and returns lifecycle statuses. Successful unmarked legacy transports keep their old accepted behavior regardless of JSON content type. emailDeliveryReady is supplied from the actual private fetch capability; Node delivery composition is unchanged. No fake deliveryURL/token is introduced.

Local tests use a mock native `send` object only. A separate actual Miniflare/workerd scenario exercises maintained login plus DO SQLite, the hosted private bridge, fixed domains/code template, lifecycle rejection/outage propagation, legacy JSON200 compatibility, strict marked-profile failures and absence of a public /send route. Its send capability is explicitly a local fake, not Cloudflare-delivered email. They verify structured shape, exact domains/admin origin allowlist, actual code/fragment profile, input rejection, status mapping, error redaction, input snapshot and one-attempt behavior. They do not use Wrangler remote bindings or send real mail.

The current [official Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/) documents structured send and a messageId result. [Domain setup](https://developers.cloudflare.com/email-service/get-started/send-emails/) remains a deployment operation outside this change.

`wrangler.email.example.jsonc` is an opt-in configuration example using an EMAIL send binding restricted to the three sender addresses. It keeps preview disabled, routes empty, workers_dev/preview_urls false and remote development sending false. The default wrangler.jsonc remains unmodified and has no send_email binding. No deployment, DNS modification, sender verification or real email was performed.

The native leaf now accepts trusted constructor options `beforeEmailAttempt`, `requireEmailBudget=false`, `emailBudgetTimeoutMs=5000`, `clock` and `cryptography`. Required mode without a callable hook rejects construction. A supplied hook is enforced even when required mode is false. After input validation/template generation, it privately creates a 13-digit bounded timestamp plus 32 cryptographically random bytes encoded as a URL-safe attempt ID, then calls `beforeEmailAttempt(Object.freeze({attemptId,purpose,to}),{signal})`. Only `admitted === true` allows one native send; budget accounting fields may accompany it. No attempt ID, denial details, callback error or private recipient is exposed in failure responses/logs. Unknown/denied/duplicate decisions return generic email_budget_unavailable without dispatch. Each actual retry requires a fresh privately generated ID and charge; no refunds or retries are performed here.

The hook wait has a finite five-second default, explicitly configurable from 1ms through 10s. A timeout aborts the supplied signal and permanently ends that invocation before native dispatch. A late durable charge remains spent and cannot resume sending. The hook must not use transaction rollback or cancellation to refund an already uncertain dispatch. If the hook is absent in optional development mode, the leaf retains its previous explicitly unbudgeted behavior; this is not production economic readiness. Hosted Worker composition now injects the required private shared-DO budget hook; configured core human admission is required for the native hosted path; sender-domain/live vendor/delivery readiness remain separate gates.

These options are constructor capabilities, rejected as message fields. The private in-process bridge is not a public mail endpoint. The leaf preserves and charges only the snapshotted validated purpose, but cannot independently certify every upstream caller is authorized to select a notice purpose. Actual provider/composition wiring and bypass tests must establish that trust before enabling production; no message-supplied flag creates a private reserve lane. No commercial caps/prices were added.

Hosted production composition rejects explicit legacy EMAIL_TRANSPORT until a budgeted adapter is independently reviewed; sandbox legacy compatibility remains explicit. This is a Waypo.link implementation restriction, not a portable protocol mandate or a restriction on OSS custom adapters. Production without email remains allowed. Native EMAIL always requires the guard and actual shared budget, in sandbox as well as production. The public initiation response is deliberately opaque for expected suppression/outage/rate/terminal cases: preserve a prepared flow receipt, or create an unpersisted synthetic one if no flow issued. It neither confirms delivery nor marks an account unreachable. Custom server adapters use the public @3sln/waypo/email-delivery branded fault port rather than serializing caller-selected error codes.
