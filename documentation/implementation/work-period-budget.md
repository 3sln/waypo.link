# Provider period work wallet

> Source-development reference: open-source Waypo commit `a57ac7d` selected by this isolated hosted candidate. Public operation remains disabled; work units and example policies are not financial approval.

This is an implementation policy, not an identity or service protocol extension. It counts operator-defined integer work credits; no conversion to currency, approved public cap, or financial guarantee is implied.

`createWorkPeriodBudget({installationId, issuer, policy, clock})` binds one local transactional metadata ledger and a protected `bootstrap/installation.workPeriodBudget` anchor. Policy declares a revision and finite UTC daily/monthly total units plus essential reserve units **included in** each total. Optional reservation must fit both its ordinary allowance and the shared total. Essential reservation may use the remaining shared total, never an extra ceiling. Both periods must allow every reservation. A trusted optional third minimumUnits argument allows a preferred prepaid batch to shrink to the available credit, provided the current operation still fits; the returned units is the actual debit. Without that argument reservations remain exact. This avoids denying one essential unit just because the normal batch is larger than remaining capacity.

Trusted deployment provisioning explicitly calls `initializeInTransaction(tx)` only when neither anchor nor ledger exists. No request or runtime construction initializes credit. Once anchored, a missing ledger fails closed even in a fresh runtime; initialization refuses to zero it. Restoring both trusted installation metadata and ledger consistently is an operator responsibility. Normal governance changes must preserve the installation anchor. For adoption into existing installations the operator deliberately invokes this provisioning step; it is not an HTTP endpoint.

Configuration changes do not create fresh keys or balances. A new policy fails closed until trusted operator `migrateInTransaction(tx, {expectedPolicy})` compares the exact old policy and replaces it while retaining current day/month spending. Lower ceilings can immediately prohibit new reservations. Migration is not authorization and must only be exposed through a separately protected operator workflow. Losing or restoring an entire database to an old backup remains outside the ledger's anti-reset guarantee.

`reserveOptionalInTransaction(tx, units)` and `reserveEssentialInTransaction(tx, units)` debit before work; `checkInTransaction(tx)` validates the existing ledger and policy without writing. All ports are local and use the caller's existing metadata transaction. They must not start nested transactions, call remote services, or acquire Native locks from held metadata transactions. The `window()`/reservation result carries revision and an absolute `notAfter` at the next UTC day boundary. Backward clocks fail against runtime-observed high-water and persisted mint/migration time. Cached effects do not globally persist a new high-water timestamp; a cold restart may therefore observe a time between its last mint and a later cached effect. It cannot cross a period backwards relative to persisted spending or mint a new allowance for an already committed period.

The bounded ngin adapter supports optional reservations. It is an engine test/adapter seam; it does not expose essential selection to apps. There are no growing attempt receipts, refund operations, app maps, or history scans: one fixed ledger plus one installation anchor. A closed typed transport helper carries known period exhaustion as429 and expired windows as503 with finite server-selected Retry-After; malformed/unknown upstream details are not exposed. Concurrent/repeated RPC reservations debit again; uncertain responses, cache loss, actor eviction and abandoned work lose prepaid credit instead of returning it.

## Service integration

`createServiceWorkEngine({periodBudget, ...})` optionally attaches the local wallet. Service lookup and account/app/fleet block debits call its optional reservation in the **same** transaction as their existing bucket debit. Cache hits still perform the existing authority transaction and read/validate the period ledger; they do not write a global ledger per effect. Day/revision binds cache keys; midnight discards unused prepaid credit. Owner-maintenance uses a separate trusted Action, separate essential cache, and Native owner authority. No HTTP/JSON field selects essential status. The Worker owner-maintenance factory accepts the same explicit port and uses a dedicated essential lookup Action, so exhaustion of ordinary period credits does not block catalog export at its lookup step. Its owner calls and usage reserve included essential units and clamp signed maintenance capabilities to the reservation notAfter. This is tested through the real catalog HTTP adapter and account maintenance engine with DI owner authority; hosted application composition still has to supply the port.

`createStorageRoutingAdmission({periodBudget, ...})` passes the same port to C's service engine. Reserved work results include wallet revision and notAfter; `issue` clamps signed A lease expiry to the period boundary and existing Native expiry/60-second bound. No C round trip is added per A patch. Expiration after committed wallet debit but before route issuance produces no lease and no refund. Previously transferred A blocks die with their signed lease; they cannot spend into the next day.

The policy is opt-in in portable core. Hosted configuration requires a complete `services.workPeriodBudget` whenever any optional service is enabled, independently of closed signup or billing. The application constructs the local bound port; the Worker uses one bound instance for ordinary services, routing and owner maintenance. Merely importing this module activates nothing. A configured but uninitialized/missing/mismatched ledger makes `/healthz` return503 with an operator action; covered service work also fails closed. Identity runtime construction does not create the ledger. Initial coverage excludes Native token work, email budget, push delivery, support effects, provider administrative operations other than current owner maintenance, background cleanup, and pre-admission Worker billing. Future essential export/revoke/contact/cleanup adapters need trusted server-selected ports and the same included reserve; this module alone does not claim those effects are all charged. Existing scopes, authentication, rate limits, row/blob limits, and fleet admission remain necessary.

## Explicit operator setup

For a new Worker installation, the protected `provisionFromOperator()` RPC provisions the installation marker then initializes the wallet when configured. If setup stops between those commits, or when adopting the wallet into an existing installation, the operator calls protected `adoptWorkPeriodBudgetFromOperator()` explicitly. Neither method is an HTTP route. Adoption refuses an existing anchor even if its ledger is missing; restoring consistent durable state or deliberately reviewed migration is required.

For Node, provision the existing installation database first, then run `npm run provision:work-period -- --config /private/provider.json --acknowledge-initialize-work-period-budget`. The private JSON may be a provider configuration or the hosted `{provider, billing}` wrapper. This command only opens an existing protected database, reads its installation binding, and creates the first anchored ledger; it does not start a server, create an account, authorize an admin, or print the config/secrets. There is no startup fallback or retry that zeros spending. Policy changes use the separate trusted transactional CAS migration API described above.

Actual Node and Worker startup/adoption/restart tests verify503 before adoption, successful explicit setup, preserved anchor after restart and503 after deleting an activated ledger. Hosted example values remain closed engineering fixtures, not approved economic limits.
