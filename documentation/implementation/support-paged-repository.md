# Bounded support storage and migration

> Source-development reference: open-source combined candidate `85bc5f4`, selected by this isolated hosted source pin. Production/public operation remains disabled; paired engine and authenticated UI/hosted qualification remain separate gates.

This is optional provider implementation policy, not an identity/notification/storage protocol extension or a price plan. Support remains disableable. The hosted Worker has no media validator and does not acquire media capability from this repository change. Hosted text feedback/staff casework must be enabled separately after paired/UI qualification; public signup is unchanged.

`support.limits` is a validated partial override of finite engineering defaults, copied/frozen by the validator. Defaults are4,096 fleet tickets,32 per owner,256 messages and128 private notes per ticket,16 enforcement proposals,1,024 critical audit events and128 rolling read observations. A ticket has512KiB of logical UTF8 text, with128MiB installation-wide. Existing media defaults remain4 ready items/4 stages,5MiB per upload,10MiB per ticket and64MiB installation-wide active/staged media; stages expire after ten minutes and tickets after30 days. These are implementation examples, not approved public launch capacity or financial guarantees. Lowering limits blocks growth while preserving existing reads/cleanup and counters. The critical-event capacity must accommodate configured mutation counts plus legacy evidence headroom.

The anchored `support/layout` marker and fixed `support/index` ledger retain fleet ticket/text/media totals, a bounded catalog-page directory, collection cursor and bounded garbage queue. An activated empty ledger remains present. Missing counters/layout/migration state fail closed, including after restart; normal requests never reconstruct or zero them. Each active owner has a bounded index and anchor for ticket summaries/idempotency references. Owner listing and create replay use constant metadata-key reads rather than scanning the fleet. Empty owner state is deleted only after that owner's last retained ticket is physically removed.

Catalog pages contain at most16 summaries. Staff listing reads one page and checks at most16 case grants before returning authorized headers and an explicit next cursor. Cursors select pages, never authority. The staff UI has first/previous/next controls and clears pagination/selected cases on account changes. Concurrent catalog changes can move page boundaries; first-page refresh provides a fresh traversal rather than a snapshot consistency promise.

Messages, private notes, proposals and audits live in bounded content pages, not the ticket header. A page is limited to128KiB of serialized UTF8 JSON—below the portable implementation's256KiB metadata guard, not a claim about Cloudflare's physical row limit. Messages/audit pages hold at most four records and proposal pages two, covering JSON escaping as well as Unicode text. Content has explicit aggregate UTF8 budgets; bounded metadata overhead/count limits apply independently. A staff ticket response hydrates its finite history; this change does not advertise constant-cost full-history reads or cover all incoming Worker bills.

Created/mutation/enforcement events remain critical evidence until ticket retention deletion. Unknown legacy event kinds are preserved as critical. Routine staff/media reads use a separate rolling observation set and cannot exhaust the space needed for enforcement. Logical audit sequence numbers preserve ordering when timestamps tie. Existing message/note actor/timestamps and proposals remain available; new messages explicitly record the actor as well as the role. Changing the observation limit never deletes critical events.

Legacy v1 data migrates only through a versioned maintenance cursor. Each committed step handles at most eight tickets, writes their content/catalog/owner pages, and advances the marker atomically. Restart resumes the cursor; transaction failure rolls back page and counter progress together. Existing ticket data remains readable through its normal authority checks. New mutations/list operations that require complete counters return a typed503 migration hint instead of treating a partial index as empty. Missing migration state is an operator repair condition, never a reset. The new layout rejects an old v1 index under an activated v2 marker.

Collection selects at most eight summaries from at most two catalog pages, deletes at most16 content-page keys per call, and dispatches at most eight existing object garbage deletions. A retiring ticket remains charged until its content pages are removed; its header then releases stock and aggregate logical-text counts atomically. Collection can continue while support is disabled. Existing support object/stage garbage semantics are retained: the active-media quota excludes queued garbage, whose separate512-key bound can represent up to2.5GiB at the fixed upload maximum. This is an explicit remaining economic/retirement limitation; it is not a new object-lease or streaming-storage design.

Focused validation uses real Node SQLite: more than64 tickets; bounded owner reads and staff grant checks;32 worst-UTF8 messages plus16 notes whose logical serialized record exceeds256KiB while every stored page stays below128KiB; more than128 routine views followed by scoped enforcement; lowered quotas, rollback and missing counters;8+2-ticket migration across restart; and bounded multi-page collection. Browser/UI and paired hosted/full-primary qualification remain separate release gates.

Support UI publication is additionally fenced to the rendered issuer/user/session/surface, refresh generation and local support operation epoch. A queued old form, delayed case response, file read or upload cannot publish into a changed context. Only its own single unchanged-owner refresh may rebind an operation; a competing refresh/action is never blessed. Support-origin administration reviews use the same existing server review/passkey/execute endpoints with guarded publication. These client checks supplement server authority; they do not supply it. The deferred genuine-response browser probe is a separate execution gate, not inferred from source or model tests.

## Initial Waypo.link text-feedback selection

The hosted package exports `WAYPO_LINK_INITIAL_TEXT_SUPPORT` from `policy-preset.mjs`. An operator may explicitly set `support: WAYPO_LINK_INITIAL_TEXT_SUPPORT` in the provider input. Composition never selects it automatically; generic/self-host defaults remain disabled. The preset selects `mode: "enabled"`, `media: false`, and the complete bounded limits listed above: 4,096 fleet tickets, 32 retained tickets per owner, 128 rolling observational reads and 1,024 critical evidence records per ticket. It preserves the separate message/note/proposal and aggregate UTF8 budgets. Media uploads remain disabled, including on Workers without a qualified validator. Exporting this preset does not enable public signup or deploy the service.
