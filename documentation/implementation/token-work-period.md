# App token admission under installation work ceilings

> Source-development reference: open-source Waypo commit `8c62e73` selected by this isolated hosted candidate. Public operation remains disabled; work units and example policies are not financial approval.

This is provider implementation policy, not an OIDC extension, price plan or authentication grant. Hosted identity-only deployments still expose app token work, so they require explicit token rate buckets plus installation weighted/period policies in `services.workBudget` and `services.workPeriodBudget` even if all storage/notification/signaling flags are disabled. Private portable-core installations retain opt-in configuration. Explicit protected operator initialization/adoption remains necessary; ordinary traffic never initializes a missing ledger.

The application passes its existing local period-budget object to the provider token-work engine. Public token entry first reserves optional lookup work, then reads the real maintained Native refresh row/client/user and terminal/family/session fences. A positively verified public refresh also reserves optional weighted family work before the maintained handler is called. Existing grant validation, scopes, rotation, revocation, credential expiry and the bounded one-shot ordinary-logout repair remain authoritative. Unknown/invalid refreshes retain the maintained native limiter; a prepaid cache never supplies authorization.

Lookup and verified-refresh block debits share the service wallet's ordinary totals. No request field or grant type selects essential spending. The included owner-exit reserve is not consumed by app refresh. Period and existing rate-bucket debits occur in the same already-existing C metadata transaction, with no nested Native/remote transaction. Cached admissions read/validate the period ledger and current profile without writing the global ledger each time. The cache key includes the UTC day boundary and wallet revision; cache loss, uncertain responses and obsolete blocks never refund credits. A preferred batch can shrink to the current operation cost when little optional credit remains.

Clock rollback, missing activated ledger and changed policy fail closed even with cached token credit. A reservation completing after its captured window is refused without refund or Native grant invocation. This does not shorten OAuth token lifetimes or turn money counters into revocation. An already admitted request-scoped maintained grant and its at-most-one positively verified logout repair may finish across a calendar boundary; their bounded work was already paid at admission. Interrupting a successful rotation merely because midnight passed could strand the freshly rotated token, so no new fragile Native mutation hook is introduced.

Period refusal before rotation returns generic OAuth `temporarily_unavailable` with 429 for exhaustion or 503 for temporary unavailability, retaining finite Retry-After/body hints. The existing public CORS/preflight wrapper exposes Retry-After and legacy X-Retry-After to browser-only public clients; exhausted optional work does not turn an OPTIONS preflight into an opaque error. A temporary refusal leaves live Native refresh rows/access tokens and owner SIDs available. The SDK preserves pending local edits and full provider retry floors rather than pretending the account was revoked. Owner sign-out, export and other essential entry paths are not reclassified as optional app token work.

This seam does not meter every authorization, sign-in, CIMD metadata fetch, device enrollment, support, email, push, federation or administrator operation, nor raw inbound Worker requests. Work units remain operator-defined and are not a dollar guarantee. Other resource/rate/Native-byte/admission guards remain required. Raising a budget through operator CAS does not automatically clear clients' previously advertised monthly retry floors; bounded provider recheck hints or a trusted resume signal remain separate operational candidates.

Validation includes actual maintained public refresh refusal with a live unchanged refresh row, valid access token and retained SID, public CORS/preflight guidance and a durable client outbox; separate engine cases cover rollback, missing ledger, cache loss/reopen, midnight/queue/commit races and last-unit reservations.
