# Ordered-log semantics and durable retry contract

Current protocol candidate; local reference implementation evidence is scoped and production release remains disabled. Provider stores opaque append-only entries ordered by one durable per-log sequence; it does not merge application state. Apps choose their own reducers/CRDTs and independent blob references. Read/append/trim namespaces bind issuer/account/client/log/incarnation. All cursor positions and revisions use safe decimal strings/opaque tokens; see log-storage-extension.md.

## Fixed operation identity

Canonical UUIDv7 Idempotency-Key includes its immutable 48-bit Unix-ms timestamp. Initial profile: retry window 24 hours, future skew 60 seconds, maximum entry 64 KiB; all provisional. SDK mints at first network submission, persists ID+original bytes+expectedHead before sending, then never rewrites ID/timestamp after uncertain result. Offline drafts can wait without IDs. An authorized client deliberately choosing a new ID makes a new append; no semantic duplicate detection is promised.

Final transaction uses trusted wall time with a durable nondecreasing time floor. Require issuedAt<=now+futureSkew and now<issuedAt+retryWindow. Never advance floor from caller timestamp. Clock rollback cannot revalidate a GC'd ID. Reject malformed/future key, expire typed 409 retry_window_expired before new append. Receipt GC and append use the same floor. Persist a monotonic rejectIssuedBefore timestamp. Receipt GC advances it from trusted time and the selected window before erasing any receipt; reject issuedAt below that floor even if a later policy lengthens the window. Never decrease the floor. Retain each receipt through its original issuedAt + window + skew deadline. Shrinking a window can explicitly expire unknown uncertain attempts; an existing same-intent receipt still reconciles its known outcome. Later widening cannot reopen erased operation IDs. Restore of this floor/receipt authority is subject to coordinated rollback safety, not a new exactly-once promise.

Intent fingerprint covers exact bytes and expectedHead, including distinction between absent and present. After UUID syntax/binding/current authority checks, receipt lookup precedes current time-window/reject-floor refusal and current-head CAS: same ID+same intent returns original cursor even after other appends/trim; changed intent: 409 idempotency_conflict. A still-retained receipt reconciles its known outcome even if policy shortened the retry window or trusted time advanced; it never allocates a new entry. An unknown/erased operation ID must pass the current fixed-timestamp window, future skew and durable reject floor before any append. New operation with mismatched expectedHead: 409 head_conflict, no event/debit; caller decides a new intent, never hidden retry. Receipt retention is at least issuedAt+window+skew. No still-valid receipt eviction: finite row cap backpressures new operations while allowing existing replay. Trim/archive cannot remove dedup authority. Receipt includes retained=false if its original event was trimmed.

Expiry after ambiguous result does not prove failure. Client preserves payload/ID and reports uncertainty; only explicit application reconciliation/new append decision can obtain a new ID. Durable read entries include operationId to help app reconciliation while history remains; no permanent result lookup/dedup promise after receipt/history expiry.

## Atomic mutation and resource accounting

Append transaction rechecks namespace/current authority/lifecycle/time/intent/expectedHead/quota and commits sequence+entry+receipt+logical usage+subscription watermark together. Crash/rollback cannot publish a ghost event or allocate a successful receipt without its event. Sequence never resets or reuses, including after trim. Payload I/O before transaction requires durable owned stage/reservation and final recheck. Unknown write outcome remains charged until settled. Replay has bounded request/read work but no second logical payload debit.

TrimBefore is destructive only below explicit committed cursor. Revision CAS prevents changing history under a stale view; trim does not grant app correctness/checkpoint guarantees. Logical retained usage may fall when entries retire; physical object/SQL liabilities, receipt rows, failed deletes, export/read pins and encrypted archive duplicates remain separately bounded. No all-history synchronous cleanup. Bound archive object fetch count and bytes read independently from returned entry count and response size: a page of tiny entries cannot force unlimited segment scans or whole-object downloads. Trim never deletes independent blobs or infers unreachable app data. Zero-byte entries consume row/receipt/work stock.

Archive immutable bounded ranges; verify object bytes/hash, then CAS incarnation/range/floor/manifest revision. Concurrent append beyond range survives. A delayed archive cannot restore trimmed entries; losing object remains durably owned garbage. Capture page highWater across all pages so continuous writers do not prevent catch-up. Reads/export pins, trim floor and GC must share a complete ownership protocol: after awaited object reads recheck live authority/floor; never turn missing bytes into empty success. Archive maintenance has bounded prepaid work and lifecycle fencing, independent of browser cookies. Crashes at each publication/delete boundary must retain data or owned cleanup liability.

## Required qualification before mounting

Pure ngin: duplicate/conflicting ID, expectedHead replay ordering, clock rollback and policy changes, inclusive through/exclusive after, empty origin snapshot, trim boundary/CAS, retry aftertrim, receipt backpressure, overflow and namespace substitution. Object/adapters: delayed archive publication versus trim, held read versus deletion, lost/partial PUT and rollback/restart, quota/physical liabilities, accepted authority revocation during I/O. HTTP/SDK: exact DTO/status/body limits, new consent scopes, signed actor dispatch, account switch/outbox uncertainty and reconnect ranges. Full engine/runtime/browser gates remain required; tiny proof alone is not archival or production evidence.
